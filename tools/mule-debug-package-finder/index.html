Getting Started

How to Use the Debug Package Finder

Go from "which package do I need?" to a pasted logger config in seconds.

Step 1: Search Your Connector

Type a connector name, vendor, or keyword (e.g. "salesforce", "aws", "sftp") into the filter box.

Step 2: Pick a Log Level

Choose DEBUG or TRACE — this controls the level attribute used in the generated log4j2 snippet.

Step 3: Copy What You Need

Click any package name chip to copy just that single package (handy for Anypoint Runtime Manager, which takes one package at a time), or use the log4j icon to copy a ready-made <AsyncLogger> XML block for all packages in that row.

Step 4: Paste & Redeploy

Paste into your project's log4j2.xml under <Loggers>, or into Anypoint Runtime Manager → Settings → Logging, then redeploy or save.

FAQ

Frequently Asked Questions

Can I contribute a MuleSoft debug package?
Yes. Update the debug-packages.csv file in the repository, then create a pull request with the change. I will periodically review and merge contributions.
What package should I set to DEBUG for HTTP request/response logs?
Set org.mule.service.http.impl.service.HttpMessageLogger (and org.mule.module.http for Mule 3 apps) to DEBUG to see full HTTP payloads and headers.
Where do I add these logger packages?
Add an <AsyncLogger name="package.name" level="DEBUG"/> entry inside the <Loggers> block of your log4j2.xml, then redeploy. In Anypoint Runtime Manager, add the same package/level under Settings → Logging without a redeploy.
Does enabling DEBUG/TRACE logging expose sensitive data?
Yes. Connectors like HTTP, Database, and Salesforce can log full payloads, headers, and credentials at DEBUG/TRACE. Enable it only temporarily and disable it once you're done troubleshooting.
Is my data sent to any server?
The connector list itself is static and all filtering happens directly inside your browser. The only network activity is an anonymous, non-personal counter increment (just a package name, no payloads or identifiers) sent when you click a package or copy a log4j2 snippet — this powers the "Most Copied" sort order. No request bodies, logs, or credentials ever leave your browser.
How does "Most Copied" sorting work?
Every time a package name or log4j2 snippet is copied, an anonymous counter for that package is incremented via a lightweight Cloudflare Worker. Sorting by "Most Copied" ranks connectors using those aggregate, anonymous counts — no cookies, accounts, or personal data involved.
